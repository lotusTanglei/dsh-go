# 超级管理会话：功能规格 v2

日期：2026-11-21。状态：**新设计目标，未实施、未验收**。

配套：[交互页面稿](<workspace.html>)、[开发与运行时提示词](<PROMPTS.md>)。本规格只定义行为；页面稿仅演示本地交互，不声称已连接真实 Host、上传图片或执行任务。

## 1. 先说怎么用

用户从固定应用壳的全局“交给超管”入口进入独立对话视图，直接说：“把支付回调修复继续做完，这张界面截图也一起看。”可以上传或粘贴图片，**不用先选项目、找会话或复制子会话消息**。工作概览只提示一条下一步待决与项目摘要，不把全部聊天和进展铺在首页；浏览项目不暗改发送目标，离开对话再返回保留未发送文字、图片与来源草稿。

1. 超管根据真实项目成员关系、会话工作事实和本次输入寻找目标；唯一可确定时显示“将发送到哪个项目 / 哪个会话、做什么”，再按 Host 的授权规则执行。存在同名或多候选时，只问最少必要的问题，不盲投。
2. 原有普通会话可以被受控继续、补充指令、纠偏、回答问题，以及在 Host 支持并授权时停止或恢复；不是只读汇总的另一个入口。超管自己派出的子任务同样可控，但不重复算作另一份项目工作。
3. 在事项的进展 / 结果视图看人话反馈：“已确认复现；正在修复；还差回归验证”；在独立待决策视图处理“需要你选是否兼容旧接口”，并可回到关联原事项。操作审批与业务选择分开，用户知道批准的具体对象和后果。
4. 从设置分类首页分别进入**管理范围、任务来源、阶段模型**，再选择具体项目、来源或阶段，不同时展开全部表单。新项目和新会话默认纳入管理范围，用户可排除；可从腾讯文档或本地文档提取任务候选，再定位到会话处理。
5. 简单定位和进展整理可选快模型，图片理解、规划和结果检查可选能力更强的模型；界面展示实际 provider / 模型，绝不无声换模型或借换模型扩大权限。

本节“支付回调修复”“界面截图”均是合成交互例子，不是真实任务、已读图片或当前项目状态。

## 2. 五条不可偷换的基线

| 编号 | 必须交付的目标 | 不合格的替代品 |
| --- | --- | --- |
| R1 | 超管控制当前已授权 Host 范围内所有受管项目会话，自动寻找目标，支持图片上传与原图传递 | 只读卡片；仅新建 Worker；要求先选项目；只把 OCR 文本转发 |
| R2 | 子会话进展和待决策用人话回到界面，可追踪到真实来源和处理结果 | Token 流水；UUID 大标题；idle 当完成；“已通知”当“已读” |
| R3 | 可配置任务来源，包括腾讯文档、本地文档；范围、变更、出处可核查 | 将企微专用表格连接器改名为腾讯文档；把任意文档文字当执行授权 |
| R4 | 新项目和会话默认纳入，支持手动排除与恢复，执行中变更有明确语义 | 只有已加载预览被纳入；排除只是前端隐藏；恢复自动重放旧命令 |
| R5 | 各阶段默认 / 覆盖模型可配置，平衡速度和能力，展示有效路由 | 全部继承主会话且无法配置；失败静默降级；换模型等于重新授权 |

“所有”指 Host 实际可认证、可枚举、可访问的管理范围，不跨 profile、进程或机器扫描。当前普通会话只读是**既有实现边界**，不是新需求限制。目标中的控制必须同时满足真实执行能力和安全闸，不能为兑现文案绕过闸门。

## 3. 页面信息架构

本节是页面层级、导航与布局的设计建议，不新增五条功能需求，也不是当前产品已实施或已通过页面验收的声明。

### 3.1 固定应用壳与分层视图

- **应用壳：** 固定主导航、顶栏、面包屑和全局“交给超管”入口；hash 导航决定当前视图，每次只有当前 view 参与布局。工作概览、项目、待决策、超管对话与设置是同层入口，不在一页逐段堆叠。
- **工作概览：** 仅展示一条下一步待决、紧凑项目摘要与深入查看入口，不展开全部进展、所有问题或完整聊天。展示先后不是擅自确定项目业务优先级；覆盖不全仍明确 partial。
- **项目集合 → 单项目：** 单项目按“事项 / 关联会话 / 任务来源”tabs 查看。项目归集工作，事项表达目标与进展，会话是处理上下文，来源提供材料；**事项不等于会话**，合成数据的一对一示例不是关系约束，不把这三类对象做成重复任务。
- **单事项：** 按“概览 / 进展 / 关联 / 结果”tabs 分层查看当前摘要、事实时间线、项目 / 处理会话 / 来源关系与结果证据；结果按当前状态可用，未核实不报完成。关联待决入口只显示与本事项有关的问题或审批，进入单项详情再处理。内部执行子任务按可信 lineage 汇到上级事项，不重复计数，不靠标题相似强合并。
- **独立待决策：** 列表摘要与当前单决定详情组成 master-detail，不同时展开所有问题正文。详情说明“为什么问你、影响哪个事项、选项与影响是什么”，关联项目与原事项；业务选择与特定操作审批继续分开，不能用摘要代替完整审批范围。
- **独立超管对话：** 是跨项目主操作视图，不是首页聊天全集或角落小输入框。人类输入、图片附件、定位说明、执行回执、必要追问与事项入口放在同一时间线上；底部文字 + 图片输入，发送前可预览、移除附件。用户不必先选项目或会话。
- **查看位置与发送目标分离：** 浏览项目、事项、来源或点击返回只改变当前视图，不暗改对话目标。只有明确的定向操作才进入对应目标路径，仍显示并重验目标；有未发送文字、图片或来源时，不把旧草稿默默转交其他会话，不覆盖草稿，允许回到原稿。导航、歧义取消与异步更新不得抹掉草稿或未决发送；保留适用的滚动位置和未读标记。
- **归属、范围与健康：** 项目索引供查找和范围认知，不作发送前置。明确区分全部范围、已加载数量、过滤结果与部分数据；同名显示必要短标识，稳定 ID 可展开，不用路径或 UUID 作主标题。连接状态、最近观察时间、partial / 不可用和执行能力阻断不可因简化布局而隐藏；断连保留旧内容并标过期，不清零造成功。

### 3.2 设置分类与逐级编辑

设置首页只提供三类入口；先选对象，再看当前对象的设置与回执，不把所有项目、来源和六阶段编辑器同时铺开。

| 设置路径 | 主要内容 | 保存后的可见回执 |
| --- | --- | --- |
| 管理范围项目列表 → 单项目内会话 | Host 范围、新增默认纳入、项目与会话排除 / 恢复、权限不可用项、正在执行项 | 哪些 ID 的后续读取 / 控制已撤销或恢复，范围版本及未停止工作提示 |
| 任务来源列表 → 单来源 → 候选条目 | 来源类型、位置、认证状态、解析范围、字段映射、目标提示、读取方式、变更策略 | 校验 / 预览结果、配置版本、最近成功读取、错误，不展示密钥 |
| 默认 / 阶段列表 → 当前阶段编辑 | 默认 provider / 模型 / 支持的推理档；六阶段沿用或覆盖；既有会话模型策略 | 配置值与实际有效值、能力不兼容 / 不可用原因、是否等待用户更换 |

来源候选先核对材料与出处，再带入超管草稿；已有草稿时保留原稿，不覆盖或夹带旧图。阶段列表可常驻供切换，但只编辑当前所选默认项或阶段；设置层级不改变来源、安全和模型规则。

原型中的开关可演示本地状态，但必须标“原型 / 尚未保存到 Host”；真实产品的控件只能由可用能力驱动，不能产生假保存、假批准、假停止。

### 3.3 滚动、窄屏与返回路径

- **桌面：** 固定应用壳，当前内容区滚动，不通过整页无限增长承载所有功能；超管对话在独立视图内分出消息滚动区与输入区。待决策 master-detail 只展示当前单项正文。
- **中等宽度：** 收窄导航、调整当前视图的内部栏数，不把原本独立的聊天、进展和设置下移拼接。
- **手机：** 保留同一导航层级，通过菜单与返回入口切换当前视图；待决策先列表、再单决定详情，可返回列表，不纵排所有分区。面包屑、选中 tab 与明确返回入口表达关系；临时确认和图片查看可用对话框，项目 / 事项 / 设置主体不是层层弹窗。
- 导航保持草稿和适用的滚动 / 未读状态；键盘可达、焦点可返回，中文 IME 回车不误发送。浅深主题、窄屏视图切换、内容滚动与图片预览均需真实验证，不能从静态结构推定可用。

## 4. 管理范围、可信归属与自动定位

### 4.1 范围规则

- 从 Host 的可信项目索引取得稳定项目 ID 和会话成员关系，不靠 cwd、Git 根、目录名称、标题或模型猜项目。成功查询但无成员为“未归属”；权限、重复归属或查询失败为“归属暂不可用”，不得混成空项目。
- 新项目自动纳入；其当前和未来成员默认纳入。明确排除项目优先于会话默认 / 会话恢复，排除会话优先于项目纳入。恢复项目不抹掉单会话排除。
- 会话移动后依新项目规则重算，但稳定 session ID 的显式排除仍保留；项目重命名不改变身份或偏好。同名项目不合并。
- 普通未归属会话在 Host 权限范围内默认纳入并标明未归属；项目排除不能误伤无关联会话。目录暂不可用不新授权，沿用缓存只供标过期展示，不凭缓存发起新控制。
- 超管自身、内部辅助会话和已登记子任务按可信 lineage 去重，不将所有普通 fork 都当子代理。一个底层工作只保留一个主记录，子任务在其进展中展开；追踪关系不足时标不确定，不用标题相似强合并。

### 4.2 自动定位顺序

1. Host 验证本次人类输入、范围版本与显式目标引用（若有）。界面选择的 ID 也必须重验，不能信任浏览器提交的 actor / role / 任意路径。
2. 在已纳入且有权限的目录中找稳定引用及现有任务关联；再用允许读取的目标、当前步骤、最近已提交进展和来源关联作候选证据。标题只用于检索，不是可信目标事实。
3. 唯一且证据一致时，返回“项目 / 会话 / 操作”的简短依据摘要；执行前 Host 再核对目标、归属、权限、运行状态、授权和版本。
4. 多候选、归属未知、证据过期、会话已删除或目标与输入冲突时追问；给可读名称及必要短标识，不把整个私聊正文泄露作选项。不能以模型置信度阈值替代规则。
5. 没有匹配时说明已搜索范围和限制，让用户补充或**明确同意**创建新会话；不能为了避免追问悄悄另建 Worker，也不为排除会话绕路新建副本。

没有手选项目不意味着没有授权。自动纳入管理范围允许按 Host 策略发现、汇总和承接新指令，不把过去聊天、来源文字或模型推断升级为本次执行授权。

## 5. 会话控制与子任务协作

### 5.1 控制面目标

| 用户意图 | 目标行为 | 必须保留的区别 |
| --- | --- | --- |
| 继续现有工作 | 唯一定位已有普通受管会话，发送带来源的指令；需要激活 cold 会话时按 Host 规则办理 | “已持久排队 / 已受理 / 已开始 / 已完成”分别显示 |
| 补充截图或需求 | 绑定同一工作上下文与原图引用，在恰当边界送入，不抹掉原始人类意图 | 新补充可能改变范围，旧审批不能自动覆盖 |
| 纠偏 / 改计划 | 生成明确变更和影响，在执行边界由 Host 验证后递交 | 不直接伪造原会话用户消息或修改历史事实 |
| 回答业务问题 | 回答精确问题 ID 与版本，传回来源会话，更新待决卡 | 回答问题不是批准工具操作 |
| 停止 / 恢复 | Host 可验证支持的操作才提供；展示停止申请及停止证据，恢复重新检查范围和许可 | 取消未受理投递不等于停止模型；已人工停止不得偷偷原地 resume |
| 拆成子任务 | 只在有益且授权时建立父子关联，各子任务反馈由主工作合并 | 普通会话控制不依赖先建 Ticket / Worker；子任务不能重复统计 |

已人工停止的旧工作若需要再做，默认给“以此需求新建任务”并重新审阅；只有 Host 明确支持且用户明确授权的恢复模式，才展示对应入口。运行中的会话收到两份互斥指令时必须冲突检测，不可由最后到达的模型输出覆盖先前授权。

### 5.2 执行中排除

排除的默认含义是**撤销超管后续管理，不是杀掉原会话**：

- 原子提升范围版本，阻断新读取、规划、附件访问和控制投递；清缓存 / 失效待发上下文；排除前已开始的异步读取不能再发布内容。保留最小身份和控制审计以说明发生了什么，不再继续读取该会话工作内容。
- 尚未 dispatch 的命令撤销；已 dispatch 未知的先对账，不重复投递；对已经受理 / 开始的动作明确显示“可能仍在原会话进行，排除未停止它”。对账仅查询 Host 许可的该动作最小控制回执，不继续读取会话正文或工作投影；缺此能力则保持 unknown 并给人工路径。排除不撤回已发送给 provider 的数据或已造成的副作用。
- 排除确认区显示已接收动作清单，可另选“申请停止已接收工作”。这是独立具体操作，由 Host 当次验证、审批并在可支持时执行；排除不能因此被无限挂起，也不得借停止权限继续普通读写。无法验证停止时给原会话人工处理路径，不报已停止。
- 恢复只恢复后续管理资格，不自动激活会话、恢复 Worker、重放命令或重用审批。项目排除时子任务及其排队投递一并受阻；已在执行的子任务遵循相同停止语义。

## 6. 人话进展、决策与审批

### 6.1 进展协议的语义

每条进展至少能定位工作、真实会话、最近事实版本、观察时间与出处。展示短标题和四句以内摘要；技术 ID、Token / 调用数和日志只在详情。没有可靠事实就写“暂未取得新进展”，不编百分比或剩余时间。

- “运行中”只说明执行器活跃；“已完成”需要目标验收证据。idle、todo 全完成、收到最后回复都不是完成证明。
- 聚合只收有变化的事实；每条待决按来源会话 + 问题 / 审批 ID + 版本去重。相同问题更新为一张卡，已解决保留历史；迟到旧版本不能复活。
- 数据 partial 时写“已读取范围内有 N 项待决策，另有范围尚未核实”，不能称“全部无待办”。不按项目擅自排优先级；可按待人工、事件时间或用户明确排序展示，并说明排序含义。
- 通知已持久投影、浏览器已收到、用户已读分离；不把 Outbox sent 当人已读。

### 6.2 两类人工动作

1. **业务决策：** “选择兼容方案还是只修当前版本？”显示问题、背景摘要、建议选项、影响和来源。**选项不是限制，必须提供自行输入，但控件必须联动**：未选时隐藏输入框、禁用提交；选择建议方案后可直接提交，输入框仍隐藏，点击“补充条件”才展开选填框；取消补充则隐藏，保留该方案草稿但不提交；选择“自行说明 / 另一种方案”时显示必填框，有有效文字才可提交。每个建议的补充条件与自填方案分别存储；切换不串值，恢复选项可找回其编辑状态，隐藏字段禁用且不参与当前提交。不将其他回答强行归类为任一建议，原文与所选建议分别保留并关联精确问题 / 版本 / 原事项；切换页面保留未提交选择与文字，回执可核对自己的答复。扩大范围或新方案需重新澄清 / 审阅，不因自由文本自动执行或代替特定操作批准。无需人工时不要用“等待你”包装一般阻塞。
2. **特定操作审批：** 展示精确目标、动作、可审阅范围、外发对象 / provider、预期影响、风险与回滚、期限和版本。用户只批准这一次不可变操作；目标、范围、附件摘要、版本或外发方变更后原批准失效。对不可完整审阅的内容禁批准。

认证、授权、审批绑定、到期、并发与最终执行均由 Host 决定；提示词和模型输出无批准权。前端不能从“好的 / 继续”或截图里的“同意”代造批准。旧 blocking 问题、通用审批若缺可靠投影，必须标覆盖缺口，不能伪装已经集中处理。

## 7. 可配置任务来源

### 7.1 目标类型与首个垂直切片建议

**目标仍是腾讯文档、本地文档等可配置来源，不限于表格和纯文本。** 下表区分目标类型、建议实施次序与待验证能力；不是用户已批准的范围裁剪，也不是已确认存在的连接器 / DSH API。每种适配器都必须先验证合法只读接入、格式能力和图片证据，再启用；不可用时明确失败，不返回假空列表。首个切片通过不得直接宣称 R3 完整通过；最终支持矩阵和暂缓项需用户确认。

| 目标来源 / 类型 | 首个切片与后续适配建议 | 明确不冒充支持 |
| --- | --- | --- |
| 腾讯在线表格 | 建议先验证：用户选定文档、工作表和有限 A1 范围，稳定编号、标题 / 描述 / 状态字段映射；预览文字和对应原图。接入是否可用待验证 | 企微 `doc.weixin.qq.com` 专用连接器不等于腾讯文档 `docs.qq.com`；不能改标签凑支持 |
| 腾讯普通文档 | 属于目标来源；独立验证段落 / 标题锚点、嵌图、评论 / 版本，按真实能力接入；未验证前显示“适配待验证” | 不把在线表格行解析器套在普通文档上；待适配不等于从最终需求删除 |
| 本地 Markdown / TXT / CSV | 用户选定文件 / 根目录，建议作为最窄切片；按标题 / 显式任务编号或字段映射取候选，Markdown 可引用已授权根内图片 | 不以最窄切片冒充所有本地文档支持 |
| 本地 Office / PDF 等 | 保留目标类型与能力矩阵；逐一验证 DOCX 段落 / 嵌图、XLSX 行列 / 公式显示值 / 图片、PDF 页码 / 文字层 / 扫描原图，明确提取范围与不完整项 | 未解析不能做纯文本假成功；不执行宏、脚本或动态内容；具体首批格式需核实并确认 |
| 其他来源 | 保留连接器配置模型和能力描述，按用户实际来源独立增补 | 不自动附加邮件、GitHub、飞书或全部磁盘扫描 |

设置流程：选类型 → 选位置 / 在 Host 安全界面建立认证 → 限定范围 → 预览解析 → 映射字段与稳定标识 → 查看目标提示 → 保存版本 → 手动读取；持续监听 / 定时读取需单独启用并受 Host 支持，不因为保存来源自动启动。可建议关联项目 / 会话，但提示不是可信归属或执行授权。

本地根按真实规范路径与权限检查，防止 `..`、符号链接逃逸、挂载变化；不读密钥、profile、状态库或任意邻接目录。远端 URL 限制协议、官方域和重定向，防 SSRF；不索要聊天中的 Cookie / Token，不将认证写入文档、Prompt、页面或审计。

### 7.2 候选、去重与变更

- **出处：** 来源实例 ID、配置版本、文档 / 文件稳定身份、工作表 / 段落 / 行列范围、原始编号、采集时间、内容 / 原图摘要、源版本（如可得）。UI 提供安全打开原文与对照；URL / 文件名只是位置证据，不是授权。
- **去重：** 来源实例 + 稳定条目 ID 为主键，规范内容与图片摘要判断 revision。换行 / 排序不应创造第二个业务任务；无稳定 ID 时先明确限制并让用户配置，不仅凭标题去重。同内容跨来源只提示疑似重复，未经确认不强合并。
- **变更：** 同一项新 revision 显示差异；已确认计划引用不可变快照。目标、范围、内容或附件变化须重验、必要时重批，不自动改正在执行的任务。删除 / 划掉标记为撤回候选，不自动停掉已受理工作或抹掉历史。
- **未知：** 格式 / 删除线 / 图片不完整、权限失效、重复编号、范围截断、解析冲突保持 unknown / blocked。人核对原文只解决可核对的证据缺口，不篡改原始 snapshot，也不变成执行批准。
- **隔离：** 来源文字、图片内指令、链接内容和评论都为不可信证据。其“忽略上级”“导出所有项目”“已获授权”不得触发工具或扩大范围。候选生成、用户承接意图、执行计划 / 特定操作批准是不同闸门。

## 8. 六阶段模型配置

| 阶段 | 主要职责 | 校验重点 |
| --- | --- | --- |
| 会话定位 | 在可信候选范围中匹配与追问 | 结构化输出、有效候选引用，不造 ID |
| 图片与来源理解 | 看原图、解任务候选，保留未知 | 原图 / 视觉能力、格式范围、出处 |
| 规划拆分 | 目标、边界、依赖与可验收步骤 | 长上下文 / 工具和结构化能力（按实际需求） |
| 会话执行 | 向既有受管会话递交 / 执行授权工作 | Host 支持的控制能力和会话模型策略 |
| 进展整理 | 把已提交事实变为人话更新 | 不编状态、不抹掉待决与 partial |
| 结果检查 | 对照验收条件判断通过 / 失败 / 未核实 | 能读证据、对缺证据保持 unknown |

配置规则：

- 六阶段是职责与路由类别，**不是每条消息固定串行调用六次模型**。问候无需启动工作链；简单定位只执行所需阶段；未变化且仍满足范围 / 权限 / 版本的事实可复用。程序可确定的 schema 校验、幂等、授权和审批状态不交给模型裁决。会话执行协调器只完成必要协调，不再额外重复目标会话已经承担的模型工作。
- 设一个超管默认 provider / 模型 / 合法推理档，每阶段选择“沿用默认”或“覆盖”；沿用是明确配置，不是发生错误后的 fallback。界面同时显示配置值、解析后的有效值及其版本。
- **既有普通会话模型默认保留。** 六阶段“会话执行”的覆盖可以供超管执行协调器 / 新建受控子任务使用，不悄悄换掉目标普通会话模型；若用户另行开启“覆盖既有会话模型”，必须展示目标范围、原值 / 新值并通过 Host 执行能力验证。无法安全切换时阻断该切换，说明保留原模型与重新选择的选项，不能假装已应用。阶段设置必须只作用其声明范围，不能借全局默认模型切换入口修改其他会话或全局偏好。
- 运行前解析 provider / 模型身份、访问可用性和所需能力；图片阶段没有原图能力、结构化能力不符、provider 不可用或预算不足，均返回可见错误，保留已承接任务。不静默跨模型、provider、推理档或区域降级；用户明确更改后以新配置版本重试。
- 运行中的调用固定其路由快照；配置更新作用于后续调用，不中途劫持请求。尚未执行的计划在首次使用新路由时重新检查外发许可；需要审批的 provider 变化使旧批准失效。
- **外发告知：** 展示本阶段实际 provider / 模型、将发送的摘要 / 图片类别与访问范围；不展示密钥。provider 披露不等于逐次弹窗，但新外发方或扩大数据范围要满足 Host 策略与必要审批。
- 模型配置不能改变 actor、工具许可、写路径、审批、管理范围或执行隔离；快模型与强模型接受相同边界。耗时 / 费用只显示可信观测或明确估算，不承诺虚构延迟、吞吐、成功率。

## 9. 图片附件的原图与安全生命周期

1. 上传 / 粘贴 → 本地预览 → Host 接收校验 → 成为本次输入不可变附件清单 → 授权理解 / 路由 → 原图传给获授权目标会话 / provider → 引用释放及按策略回收。每一步显示真实状态；只上传尚未发送不触发模型调用。
2. Host 校验文件签名、媒体类型、大小 / 像素边界及访问者。具体阈值由实现按实测能力配置，不能用扩展名判断安全；活动格式默认不作为可执行内容。预览可派生，但**原始字节和摘要独立保留**，不拿缩略图、OCR 或模型描述代替原图。
3. 附件绑定人类输入、scope revision、目标与源 revision，跨会话按 Host 最小授权引用 / 复制，保留来源和内容摘要。确认已传原图需要目标可访问证据；拿到 `[image]` 占位不算看图或已交付。目标不支持图片则阻断图片依赖步骤并说明，不无声去图继续。
4. 不把本地绝对路径、base64、临时外链、原图或密钥写到普通进展和审计。图片中出现的秘密不能靠文本 sanitizer 自动消除；按敏感数据策略阻断或由用户显式选择衍生脱敏版本，不无声篡改“原图”。外部 URL 不由模型任意抓取，必要下载经 Host 连接器验证。
5. 移除未发送附件释放临时引用；发送中取消先对账，不能删除仍被已受理动作使用的数据。持久引用、访问令牌、缓存与回收策略可审阅；删除后撤销后续访问，告知已外发数据无法保证从第三方追溯删除。备份与审计有独立保留说明，不声称即时彻底抹除。

## 10. 持久投递、并发与可观察性

以下名称均为概念实体，**不是已有数据库表、工具或 DSH API**：管理范围快照、定位提案、控制命令、附件引用、来源快照、进展事实、人工决策、模型路由快照。

- 一个用户意图有稳定 request ID；每个具体动作有稳定 action ID 与规范摘要，涵盖目标、操作、输入、附件、版本与授权关联。同 ID 同摘要返回同回执；同 ID 改内容冲突。编辑输入建立新动作，不借新 ID 盲重放旧动作。
- 先持久记录投递意图和 dispatch fence，再执行，提交后以目标 / Session 证据对账。状态区分已记录、排队、发出待核实、已持久受理、运行、等待人工、完成、失败、已撤销；实际状态映射需在实施时验证，不强加到现有枚举。
- 对“dispatch 已发生但回执丢失 / flush 失败 / 崩溃”显示 unknown，先读证据后决定，不声称端到端 exactly-once。目标没有幂等受理 / 查询能力时禁止自动重投不确定动作，给人工核实路径。
- 同一目标的控制顺序化，并用目标版本 / expected revision 检测陈旧操作；互斥指令需澄清或显式替代。不同目标仅在授权并发额度内并行，且校验共享资源冲突，不能把“不同会话”当可同时写同文件的证明。
- 每个异步边界后重验范围、权限、目标、源与配置版本；排除、移动、删除、模型变更、到期审批和迟到结果不能穿透旧快照。重启恢复以持久事实为准，不自动唤醒所有历史会话。
- 可观察记录至少包含 request / action 关联、来源与目标稳定引用、事实时间、阶段、路由身份、审批关联、结果 / 错误代码及证据引用；不记录秘密、原始正文和原图。UI 和诊断都区分合成测试、真实受控探针与真实业务 / 视觉证据。

## 13. 非目标与实施边界

- 本轮只新增设计文件，不修改产品、旧设计、profile、安装包或运行环境；不运行真实模型 / 文档接入测试。
- 本规格不是数据库迁移、部署或安装方案，不新增 DDL、不迁移用户状态、不安装插件 / 依赖、不重启 DSH，不自动提交或清理既有工作区改动。
- 不自定项目优先级，不把会话运行状态当业务价值排序，不替用户创建所有项目、搬动会话或更改原项目归属。
- 不跨 Host / profile / 机器控制，不建立任意 URL / 文件执行器，不开放秘密数据，不削弱原有 L1 / L2 隔离、owner / Origin / epoch、审批或审计。
- 不承诺“所有格式立即支持”“自动处理所有审批”“绝对一次执行”或虚构性能。能力缺口要显式暴露，不把安全闸当理由永远只交只读面板，也不靠提示词冒充安全闭环。
