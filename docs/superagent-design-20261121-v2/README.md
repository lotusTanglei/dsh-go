# 超管 v2：需求驱动设计包

日期：2026-11-21。性质：**页面与功能设计、开发和运行提示词，不是插件实现、部署或验收声明。**

## 先看什么

1. [可交互页面稿](<workspace.html>)：直接打开；没有依赖、不需要启动服务。
2. [功能规格](<FUNCTIONAL-SPEC.md>)：五条需求如何落到工作流程、功能边界与验收。
3. [提示词包](<PROMPTS.md>)：可复制的开发总提示词，以及超管各阶段运行提示词。

## 五条需求如何落到页面

| 用户需求 | 页面落点 | 主要交互 |
|---|---|---|
| 超管控制各项目会话，自动找目标，支持图片 | 独立超管对话视图；全局“交给超管”入口 | 直接说需求；自动定位并回显目标；歧义询问；已有会话可接收补充；图片选择/粘贴/拖入/预览/移除 |
| 子会话进度与决策用人话展示 | 事项详情的进展 / 结果；独立待决策列表与单项详情 | 概览只提示一条下一步待决；完整进展进入事项查看；决定关联原事项；范围澄清与危险操作审批分开 |
| 腾讯文档、本地文档等来源可配置 | 设置 → 任务来源列表 → 单来源 → 候选条目 → 超管 | 来源位置、归属、提取规则、发现后动作、启停、出处核对；实际适配范围不能冒充已实现 |
| 新项目与会话自动纳入，可排除 | 设置 → 管理范围项目列表 → 项目内会话 | 模拟自动发现；项目/会话排除与恢复；项目规则覆盖后续会话；排除不等于停止 |
| 各处理阶段可配置模型 | 设置 → 阶段列表 → 当前阶段编辑 | 默认模型＋六阶段覆盖；校验图像能力；保留既有会话模型；无静默切换 |

## 页面层级与日常路径

固定应用壳由主导航、面包屑、全局“交给超管”入口与当前内容区组成；通过 hash 导航切换视图，**每次只有当前 view 参与布局**，不是把所有功能堆成一张长页面。

```text
应用壳：工作概览 / 项目 / 待决策 / 超管对话 / 设置
全局：交给超管；面包屑与返回路径

工作概览：一条下一步待决 + 紧凑项目摘要，不展开全部进展
项目集合 → 单项目 [事项 | 关联会话 | 任务来源]
              └→ 单事项 [概览 | 进展 | 关联 | 结果] → 关联待决
待决策：列表 → 单决定详情（桌面 master-detail）→ 原事项
超管对话：独立主操作视图，文字 + 图片 → 定位 / 追问 → 回执 → 原事项
设置首页 → 管理范围项目列表 → 项目内会话
         → 任务来源列表 → 单来源 → 候选条目
         → 阶段列表 → 当前阶段编辑
```

- 工作概览负责“下一步看什么”，不是项目、全部进展、所有问题与聊天的全集；选哪条待决只表示展示顺序，不替用户决定业务优先级。
- 超管对话是随时可达的跨项目主操作视图，不是首页铺满的聊天记录或角落小输入框；直接交代要求，不强迫先选项目或会话。
- 项目归集事项；事项是要完成的工作，会话是处理上下文，来源是材料，待决关联原事项。**事项不等于会话**，示例的一对一关系不是产品限制。
- 浏览项目、事项或返回上层只改变查看位置，不暗改发送目标；明确“补充给此会话”等动作才进入目标选择路径。导航和歧义取消保留文字、图片及来源草稿，返回后可继续，不把旧草稿默默转交新目标。
- 原普通会话“只读汇总”是旧实现边界，**不是本轮目标功能的限制**。新设计中受管普通会话也应能接受授权指令。
- 内部执行子会话归上级事项汇总，避免一件事在列表和计数里出现多次；事项的结果页按结果状态可用，未核实不包装成完成。
- 配置与技术诊断退出日常主区；连接失败、执行受限等重要状态不能被隐藏。以上层级与布局是设计建议，不是已实施或通过验收的声明。

## 可以怎么体验

打开[页面稿](<workspace.html>)后：

1. 从工作概览的一条“需要你决定”进入待决策详情；沿出处进入原事项，再返回项目。概览不展开全部事项正文。
2. 进入项目集合 → 单项目，切换“事项 / 关联会话 / 任务来源”；进入一件事项，分别看“概览 / 进展 / 关联”，在已结束的合成事项中查看“结果”。这些是关联视图，不是重复任务清单。
3. 点全局“交给超管”，进入独立对话视图。点“试：继续已有工作”并发送，查看原会话的目标回执；它不会另建合成会话。再输入“继续处理一下。”并发送可体验歧义选择，取消保留草稿。
4. 添加 PNG/JPEG/WebP 图片，查看缩略图或原图、移除；切到项目再返回对话，核对草稿和图片仍在、发送目标未被浏览动作改写。演示限制 4 张、单张 5MB，**不是最终产品配额**。
5. 待决策未选择时不显示输入框、不能提交。选建议可直接答，点击“补充条件”才展开选填框，可取消；选“自行说明 / 另一种方案”才显示必填框，有效输入后可提交。各选项草稿独立保留，切换不串值，隐藏内容不随本次答复提交。提交回执能核对原文，答复关联原事项 / 原会话；不等于操作批准。
6. 进入设置首页 → 管理范围 → 一个项目，再排除 / 恢复项目或其中会话；返回项目列表可模拟发现新项目。排除有在途工作时会解释其后果。
7. 进入设置首页 → 任务来源列表 → 添加来源 → 单来源 → 候选条目，核对合成出处后带入超管草稿；已有草稿时先保留原稿，不覆盖。**不会读取真实链接或本地文件。**
8. 进入设置首页 → 阶段模型，选择“图片与来源理解”，只编辑该阶段，将其改成文本模型后点击“校验并保存演示配置”，观察能力阻断。

## 视觉与响应式设计

- 以蓝白、低饱和灰分区，减少无意义大数字、百分比和常驻技术信息。
- 桌面：固定导航 / 顶栏 / 应用壳，仅当前内容区滚动；项目与事项各有详情层级，待决策使用列表与当前单项详情，不常驻右栏展开所有进展。
- 中等宽度：收窄导航并调整当前视图内部栏数，不把对话、进展与设置接成长条；超管对话保留独立消息滚动区和输入区。
- 手机：通过导航切换相同层级的视图，待决策列表与单项详情分别进入并可返回；不把所有分区纵排。对话框只用于临时确认或图片查看，不代替项目 / 事项 / 设置层级。
- 面包屑、明确返回入口和选中 tab 表达当前位置与关系；只显示当前层级的简短摘要，完整范围、原始记录、依据与审批详情按需进入，授权内容不得为了好看而截断。布局仍需真实响应式与可访问性验证，不以原型结构冒充已验收体验。

## 原型边界与未做事项

- 全部项目、会话、进展、来源、模型和决策均为**合成数据**。自动定位使用明确标注的确定性演示规则，不是实际模型检索。
- 图片仅在当前页面通过本地对象 URL 预览，不上传、不识别；其他输入也不会发送。刷新会清空演示状态。
- 设置仅在内存生效；没有保存 profile、凭据、文件、数据库、全局默认模型，也没有创建真实定时任务。
- 腾讯普通文档等适配能力标为待验证；不能把企业微信表格连接器当作通用腾讯文档支持。普通文档和其他本地格式仍属于目标支持范围，具体适配需验证后交付，不能悄悄裁剪用户需求。
- 当前生产执行隔离闸未因本设计解除；“自动纳入”“路由准确”“模型选得合适”都不能代替执行权限和隔离验证。
- 未改变项目既有执行顺序或优先级；未修改当前运行的 DSH 页面或插件。

## 验证口径

本轮仅对交付文件做静态结构、JavaScript 语法、内部引用和离线边界检查，并进行独立 UI/UX 与安全语义审查。没有浏览器控制，因此**未完成实际渲染、点击、响应式实图、Host 会话控制或生产执行验证**。静态检查不等于产品验收。

## 使用提示词包

- 开发时先使用[提示词包](<PROMPTS.md>)中的开发总提示词，要求代理核实当前安装版 DSH 扩展点，再按可验收的垂直闭环实施。
- 运行提示词为拟定的角色协议，不是安装文件，不能靠复制文本自动获得不存在的工具或权限。
- 五条需求是用户基线；阶段拆分、视觉布局和实现切片是本轮设计建议。变更业务范围、执行授权或支持类型需要明确说明，不能由开发代理自行削减。
