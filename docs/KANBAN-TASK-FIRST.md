# 2026-11-21 · 工作区任务优先版式

## 起点：实际使用，不是功能排列

用户最新实图已加载跨会话版，仍明确否定视觉与交互。图片是运行中的产品证据，不能继续用“没刷新”解释。旧版把对话辅区塞成信息墙、把空台账撑成四个通高桶、让顶部范围声明与搜索挤走操作；最重要的任务与决策反而无中心。测试数不是设计验收。

本轮沿已选方案03“看板流转”，不再让用户选稿，不增加后台功能或另开管理器。

## 单一布局

```text
超管 · 连接状态    仅规划/执行状态    待审阅  刷新  系统
────────────────────────────────────────────────────
工作台          搜索 / 结果筛选 / 新建计划 │ 交给超管  历史
待你决策（有事项才出现）                  │ 新回复 / 简短引导
其他会话的工作 · 只读     查看全部/来源   │ 最近记录（折叠）
目标 / 进展 / 明确问题 的紧凑卡           │
任务看板             已登记任务/范围详情 │
待处理 → 运行中 → 等待中 → 已结束         │ 规划任务 / 问一问
实际任务卡；真空时合并一个短空态          │ 输入 → 生成计划
```

- **任务在左、对话在右**：主区使用剩余宽度，日常辅区304px；审阅计划/回复时辅区可扩至半宽、最多560px。DOM任务优先，不用CSS倒置键盘顺序。
- **单一主区滚动**：决策、来源和任务统一纵向滚动，不在四列再建四个内部滚动桶。详情定位于主区而非滚动内容，保持完整原文/审批/结果入口。
- **减少默认噪声**：步骤与Token移至任务详情；attention不展开原始对象，完整记录在详情。只读运行状态和采样时间可展开；长范围说明在明确详情，不让安全或错误消失。
- **跨会话按项目组织、不冒充正式任务**：沿用DSH Workspace真实成员关系，项目标题在会话工作上方，同名项目不合并，unknown与未归属区分。主区按当前返回会话分组，最多3项目、每项目1条；来源按已加载页聚合且只称已加载会话数，不承诺项目全集。详见[项目归属](<KANBAN-SESSION-COVERAGE.md>)。不将Agent运行状态归入Ticket四列，也不把会话数算成任务数。卡片只显示已有目标、当前进展（缺进展则下一步）及显式问题；完整目标/下一步/问题在来源中可读，不依赖鼠标悬停。排除和恢复沿原来源入口。
- **空态必须可信**：所有四列明确total=0、items为空、hasMore=false，且无工作区/看板错误，才合并空态；scope未知只说“尚未返回记录/范围待确认”，筛选无结果独立文案，不宣称用户没工作。范围说明在看板旁，来源失败在来源块一行显示。
- **克制顶部**：连接是次级小状态；仅规划/执行未知小安全位常显、可展开完整边界；搜索筛选属于工作台而非全局。发送不可用显示在输入旁，不用一整排重复横幅。
- **对话只负责沟通**：保留新回复发现与原始历史入口，最近记录默认折叠，不复制主区的决策/来源，也不再显示巨大“无需决策”欢迎牌。草稿、未确认请求和任务补充目标保持原契约。

## 响应式与完整审阅

以插件实际容器宽度，而非浏览器窗口宽度断点：

| 容器 | 布局合同（源码，非实测） |
|---|---|
| >1050px | 左任务、右304px辅区，四列等分剩余宽度，无190px硬下限 |
| ≤1050px | 完整任务/对话切换，默认任务；新建、审计划、读回复沿原动作切对话 |
| ≤720px | 任务两列状态分组、统一纵向滚动，不靠横滚找末列 |
| ≤440px | 状态分组与来源卡单列，输入和详情仍可达 |
| 低高度 | 缩短输入默认高度，允许编辑区独立滚动，不删除未确认回执恢复操作 |

切换到已隐藏输入区后以React提交后的effect恢复焦点；计划、回复、确认对话框的原inert、焦点返回和Escape链保留。完整scope/allow/deny/指纹/到期/理由与二次确认不做截断，也不为视觉简化越过安全门。
