# P1 · 骨架 + 领域 + 存储

你负责实现 `dsh-superagent` 的 P1 阶段。仓库根目录就是工作目录，`docs/` 里已有完整设计，**按文档实现，不要重新设计**。

## 本阶段只做一件事

建立**可加载的空 bundle + 领域层 + SQLite 存储 + 单测**。

**不写任何会话逻辑**：不碰 `ctx.subagents`、不建 Session、不写 Router/Worker/Watchdog。那些是 P2 的事。

然后 `--dump-config` 确认出现本包的一层。

**必须给出**：命令、真实输出、结论。
**不通过就停**，报冲突、给两个备用方案（手改 profile `package.json` + `cordis.patch.yml` 是其中之一），不要自己硬绕。

顺带验证：`node:sqlite` 在 Electron 主进程里的 `DatabaseSync` 事务与 WAL 行为是否与普通 Node 一致。

## 第二步：包骨架

```
package.json      name=dsh-superagent, type=module, engines.dsh=">=0.2.2 <0.3.0"
                  dsh.bundle.patch=./cordis.patch.yml
                  exports: "." → lib/index.js, "./client" → lib/client.js
tsconfig.json     ESM / module=NodeNext / strict / noUncheckedIndexedAccess / outDir=lib
vitest.config.ts  include tests/**/*.spec.ts
.gitignore        node_modules lib .research *.sqlite *.sqlite-*
```

依赖只允许：`typescript`、`vitest`、`@types/node`。
**不要引入 better-sqlite3 或任何原生依赖**，用 `node:sqlite`。

`src/index.ts` 先写最小版本：导出 `name` 和 `apply(ctx)`，只打一行 `[superagent] loaded`，`cordis.patch.yml` 只插一行。

## 第三步：领域层 `src/domain/`

| 文件 | 导出 |
|---|---|
| `ids.ts` | 品牌类型 + `brand()` |
| `trigger.ts` | `Trigger` `Actor` `TriggerDisposition` 及构造/校验 |
| `thread.ts` | `Thread` `ThreadRef` + `threadKeyOf()` |
| `policy.ts` | `Policy` + `policyVersion()`（sha256 规范化 JSON） |
| `eval.ts` | `Eval` `Decision` + 状态转移 |
| `mandate.ts` | `Mandate` + `canGrant()` `canWithdraw()` `revalidate()` |
| `ticket.ts` | `Ticket` + `TicketBrief` + `AcceptanceCriterion` + `transition()` 转移表（001 §7） |
| `assignment.ts` | `Assignment` + 状态转移 |
| `approval.ts` | `Approval` + 状态转移 |
| `invariants.ts` | I1–I11 的判定函数，纯谓词（含 `isOrphan(a, liveSessionIds)`） |
| `index.ts` | 统一出口 |

**硬约束**

- **不得 import 任何 `@deepseek-ai/*`**，也不得 import `node:fs`/`node:sqlite`——这一层必须零 IO。
- 全部 `readonly`，状态变更返回新对象，不就地修改。
- 非法转移抛带上下文的错误（`ticket: running → ended 缺少 outcome`），不要静默返回。

## 第四步：存储 `src/store/`

| 文件 | 内容 |

| `migrations/001_init.ts` | **逐字照抄 `004 §2` 的 DDL**（16 张表 = 14 张业务表 + `schema_migrations`/`kv`，索引齐全） |
| `repos/*.ts` | 每表最小读写：insert / get / listByState / updateState |

**不要改表结构**。若发现 DDL 有错，先停下来报，不要自己加字段。

## 第五步：配置 `src/config.ts`

导出 `Config` 接口 + `DEFAULT_CONFIG` + `validateConfig(cfg)`（纯函数）。
字段照 `002 §7` 抄全。

**本阶段不接 Schemastery**：`@deepseek-ai/schemastery` 尚未验证能否在本包解析，P2 装插件时再换。这一条写进代码注释，别让人以为忘了。

## 验收（缺一不算完成）

```sh
pnpm typecheck && pnpm test && pnpm build
```

单测必须覆盖这六组 + 两个辅助：

| # | 用例 | 断言 |
|---|---|---|
| D1 | 去重 | 同 `(source, externalId)` 投 3 次 → `trigger` 表 1 行 |
| D2 | Thread 单 Eval | **只测纯谓词**；"并发 3 条只 1 个 running"是 engine 行为，验收在 P3，**不要造假并发测试** |
| D3 | Ticket 恢复 | ended + human → open；ended + bot → 拒；`stoppedByHuman` → 拒 |
| D4 | Policy 版本 | 旧版本 Eval 裁决被拒 |
| D5 | Mandate 变更面 | grant / withdraw / revalidate 三正三反；**外加导出面断言：没有第四个 mutator** |
| D6 | I11 孤儿判定 | `isOrphan(a, live)`：live 里没有的 sessionId 判 orphan；全活判空；`ended` 缺 `endedReason` 被拒 |
| D7 | 迁移 | 空库 → migrate → 16 张表 + 索引齐全；重复 migrate 幂等 |
| D8 | 打包 | `node -e "import('./lib/index.js')"` 能加载 |
