# Go v1 范围冻结（SCOPE-V1）

日期：2026-11-24。状态：**已逐项确认**（Q1–Q15，见 §8）。本文件是 v1 的唯一权威边界；`000-overview`、`007-plan`、`superagent-design-20261121-v2` 与本文冲突时以本文为准，那三份保留为历史设计记录。

## 0. 一句话

Go 是跑在 DSH 上的单机、单用户“超管”：一个入口，既能控制你已有的受管会话，也能自己派 Worker，进展与待决策用人话回到同一界面。

## 1. 终态（v1 之后继续）

- 两者都在：接管已有受管会话 + 自己派 Worker。
- 单入口工作台；单机、单用户；不跨 Host/profile/机器；不做工作流引擎、不做多租户。
- 外部数据来源（腾讯文档、本地文档、GitHub issue、其他在线文档）**不在 v1**，下一版重新设计接入；不是永久删除需求。
- 阶段模型默认 + 六阶段覆盖可配。

## 2. v1 必须（缺一不算 v1）

五条基线中，v1 交付 **R1 / R2 / R4 / R5**；**R3（外部来源）整体后置到下一版**。

| # | 要求 | 验收口径 |
|---|---|---|
| 1 | 单入口工作台：工作概览 / 项目 / 待决策 / 超管对话 / 设置 | 你的实图 + 点击 |
| 2 | 范围管理：项目→会话默认纳入、排除/恢复、跨重启保留 | Host 回执 + 实图 |
| 3 | 控制已有会话：继续/补充/纠偏/停止；投递前确认目标与内容；持久回执 | 真实 Host 一次继续、一次停止 |
| 4 | 图片：上传/粘贴，原图随消息投到目标会话 | 真实回执 + 实图 |
| 5 | 待决策：Host 有投影的 timed 问题 + Go 自家审批；其余明确标“未覆盖” | 实图 |
| 6 | 台账：幂等、重启恢复、unknown 不换 ID 重发 | 自动门禁 |
| 7 | 阶段模型：默认 + 六阶段覆盖；真路由 = 调用前授权 + 回执核对 + 披露 DSH 无原子 dispatch 的窗口 | 自动回执 + 实图 |
| 8 | Go 的 Worker 真跑一个任务往返（L1/L2 见 §5） | 真实往返回执 |
| 9 | 验收：你实图 + 真人点击（页面清单见 §6） | 你本人 |

## 3. v1 明确不做（下一版 / 后置）

- 外部来源：企微文档、腾讯文档、本地文档格式矩阵、GitHub issue、其他在线文档；验签、长连接、轮询、写回。
- legacy blocking 问题与通用审批的集中投影（Host 无完整投影）。
- 跨 Host/profile/机器、多用户 RBAC。
- 备份/清理策略、成本曲线、大规模压测。
- 工作流 DSL、长期记忆/向量库。
- 旧七页只读面板（已被单入口工作区取代，不恢复）。

## 4. 使用规则（怎么用决定需求）

- **意图优先，不设关键字**：你用自然语言说；超管结合真实项目成员关系、会话工作事实和本次输入定位目标。唯一可确定 → 回显“要发到哪个项目/会话、做什么”；多候选/同名 → 只问最少必要的问题；不盲投。
- **每次投递前由你确认目标与内容**，模型判断错也不会误发。
- “继续/接着做”与“新做个”是意图示例，不是触发词；分不清就问。
- 待决策只列能拿到投影的两类（§2 第 5 项）；拿不到的留在原会话处理，界面注明未覆盖。
- 新任务由 Go 起 Worker；继续已有工作走会话控制；边界由意图判断，必要时追问。

## 5. 安全与执行

- 已核实：Host 对 `ctx.agents` 的投递/取消/恢复**不做 owner 或审批校验**；Go 自己的范围/owner/审批闸是唯一屏障。
- L1（票根）：插件自建 Agent，`meta.cwd` 设为票目录，不走会继承父根的 spawn 路径。
- L2（写边界）：每票使用**不含凭据/秘密的工作副本**；Worker 的 shell 换成 Go 自带、用 macOS `sandbox-exec` 包住整个进程树；原生写工具限票目录。承诺是“进程树越不出票目录”，不是逐文件 glob。
- 在 L1/L2 用真实反例（heredoc / python / 后台进程 / 跨票）证明前，生产 Worker 保持 fail-closed。
- 审批策略 never 返回 `rejected`（不是 `unavailable`）；日志与面板不出现密钥/token/私有 URL。
- 若 L1/L2 需要核心、依赖或权限变更，单独报告影响并取得授权。

## 6. 验收

- **你实图 + 真人点击**：工作概览、项目/事项、待决策、超管对话 四块；设置里的“管理范围”“阶段模型”两个编辑页；主路径窄屏至少一次。
- **真实 Host 回执**：一次会话继续、一次会话停止、一次 Worker 往返。
- **自动门禁**：typecheck / test / build / pack 全绿（在当前 HEAD 上重跑，不引用历史数字）。
- 测试数、静态审查、AST 断言只作前置，不替代视觉与点击。

## 7. 顺序与发布

1. **a**：会话控制（跨会话投递）——先做；做完可给你 dogfood 版（不算 v1）。
2. **b**：Worker 隔离（L1/L2）——证明通过后并入。
3. **v1 完成** = §2 全部 + §6 全部通过。

阶段完成只简报进度，不逐切片停。

## 9. 实现依据（已核实，2026-11-24）

- 安装版 DSH 0.2.2-rc.5 / Electron 44.7.0 / Node 24.21.0。
- 可用：`ctx.agents.get(id)` / `list()`、`agent.followup/steer/inject/cancel`（live）；`ctx.agents.resume({resumeSessionId})`（cold，需自行挂 preset、无写锁冲突）；`ctx.sessionQuery.listSessions()`；`ctx.workspaceRegistry.list()`；`ctx.attachments.saveImage` + image ContentBlock。
- 缺口：无 `session.activate`、无按 sessionId 的通用 `send`；`docs/008-dsh-api-map.md:103` 的 `send(m,target,wakeup)` 中 target 是 inbox 边界（`next-turn|next-step`），不是 sessionId——该行需更正。
- 隔离反证：L1 spawn 继承父沙箱根；L2 目录策略无逐 glob，native/shell 可写 deny/unlisted 路径（`probes/kanban/s0-20261118-202300-result.json`）。
- 企微 MCP 连接器只读，覆盖 `doc.weixin.qq.com`，不覆盖 `docs.qq.com`；按 Q13 移出 v1。
